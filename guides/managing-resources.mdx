Resources are the core entities in Open PMM. Every product, feature, initiative, and milestone you track is represented as a resource, giving you a unified data model across your entire product portfolio. This guide covers every operation in the resource lifecycle — from creation through deletion — with example curl commands and annotated request and response bodies.

## Resource fields

Before making requests, familiarise yourself with the fields that make up a resource object.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | string | — | System-assigned unique identifier. Read-only. |
| `name` | string | ✓ | Human-readable name for the resource. |
| `type` | string | ✓ | Category of the resource. See accepted values below. |
| `status` | string | — | Lifecycle state of the resource. Defaults to `"draft"`. |
| `metadata` | object | — | Arbitrary key-value pairs you define. |
| `created_at` | string | — | ISO 8601 timestamp. Read-only. |
| `updated_at` | string | — | ISO 8601 timestamp, updated on every write. Read-only. |

### Accepted values for `type`

| Value | Description |
|---|---|
| `"product"` | A top-level product in your portfolio. |
| `"feature"` | A distinct capability or user-facing behaviour. |
| `"initiative"` | A strategic theme grouping multiple features or milestones. |
| `"milestone"` | A time-bound delivery checkpoint. |

### Accepted values for `status`

| Value | Description |
|---|---|
| `"draft"` | Work in progress; not yet active. Default value. |
| `"active"` | Currently in progress or live. |
| `"archived"` | Completed or deprioritised; hidden from default list views. |

## Create a resource

Send a `POST` request to `/v1/resources`. Include `name` and `type` in the request body. All other fields are optional.

```bash
curl -X POST https://api.open-pmm.com/v1/resources \
  -H "Authorization: Bearer $OPEN_PMM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Payments v2",
    "type": "initiative",
    "status": "active",
    "metadata": {
      "quarter": "Q1-2025",
      "owner": "payments-team"
    }
  }'
```

**Request body**

```json
{
  "name": "Payments v2",
  "type": "initiative",
  "status": "active",
  "metadata": {
    "quarter": "Q1-2025",
    "owner": "payments-team"
  }
}
```

**Response — `201 Created`**

```json
{
  "id": "res_04ef1a3b5c7dg2hi8jklmn4o",
  "name": "Payments v2",
  "type": "initiative",
  "status": "active",
  "metadata": {
    "quarter": "Q1-2025",
    "owner": "payments-team"
  },
  "created_at": "2024-11-15T12:00:00Z",
  "updated_at": "2024-11-15T12:00:00Z"
}
```

## Read a single resource

Retrieve a resource by its `id` using a `GET` request.

```bash
curl https://api.open-pmm.com/v1/resources/res_04ef1a3b5c7dg2hi8jklmn4o \
  -H "Authorization: Bearer $OPEN_PMM_API_KEY" \
  -H "Content-Type: application/json"
```

**Response — `200 OK`**

```json
{
  "id": "res_04ef1a3b5c7dg2hi8jklmn4o",
  "name": "Payments v2",
  "type": "initiative",
  "status": "active",
  "metadata": {
    "quarter": "Q1-2025",
    "owner": "payments-team"
  },
  "created_at": "2024-11-15T12:00:00Z",
  "updated_at": "2024-11-15T12:00:00Z"
}
```

If the resource does not exist, the API returns `404 Not Found`.

## List resources

Retrieve a paginated list of all resources in your account using a `GET` request to `/v1/resources`.

```bash
curl "https://api.open-pmm.com/v1/resources?limit=20" \
  -H "Authorization: Bearer $OPEN_PMM_API_KEY" \
  -H "Content-Type: application/json"
```

**Response — `200 OK`**

```json
{
  "data": [
    {
      "id": "res_04ef1a3b5c7dg2hi8jklmn4o",
      "name": "Payments v2",
      "type": "initiative",
      "status": "active",
      "created_at": "2024-11-15T12:00:00Z",
      "updated_at": "2024-11-15T12:00:00Z"
    },
    {
      "id": "res_05gh2b4c6d8ei3jk9lmnop5p",
      "name": "Onboarding Checklist",
      "type": "feature",
      "status": "draft",
      "created_at": "2024-11-14T08:15:44Z",
      "updated_at": "2024-11-14T10:30:22Z"
    }
  ],
  "next_cursor": "cursor_eyJpZCI6InJlc18wNWdoMmI0YzZkOGVpM2prOWxtbm9wNXAifQ",
  "has_more": true
}
```

To fetch the next page, pass the `next_cursor` value as a query parameter:

```bash
curl "https://api.open-pmm.com/v1/resources?limit=20&cursor=cursor_eyJpZCI6InJlc18wNWdoMmI0YzZkOGVpM2prOWxtbm9wNXAifQ" \
  -H "Authorization: Bearer $OPEN_PMM_API_KEY" \
  -H "Content-Type: application/json"
```

Continue paginating until `has_more` is `false`.

## Update a resource

Send a `PUT` request to `/v1/resources/{id}`. Partial updates are supported — you only need to include the fields you want to change. Fields you omit remain unchanged.

```bash
curl -X PUT https://api.open-pmm.com/v1/resources/res_04ef1a3b5c7dg2hi8jklmn4o \
  -H "Authorization: Bearer $OPEN_PMM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "archived",
    "metadata": {
      "quarter": "Q1-2025",
      "owner": "payments-team",
      "completed_at": "2025-03-31"
    }
  }'
```

**Request body**

```json
{
  "status": "archived",
  "metadata": {
    "quarter": "Q1-2025",
    "owner": "payments-team",
    "completed_at": "2025-03-31"
  }
}
```

**Response — `200 OK`**

```json
{
  "id": "res_04ef1a3b5c7dg2hi8jklmn4o",
  "name": "Payments v2",
  "type": "initiative",
  "status": "archived",
  "metadata": {
    "quarter": "Q1-2025",
    "owner": "payments-team",
    "completed_at": "2025-03-31"
  },
  "created_at": "2024-11-15T12:00:00Z",
  "updated_at": "2025-03-31T17:45:00Z"
}
```

The `updated_at` timestamp always reflects the time of the most recent write.

## Delete a resource

<Warning>
  Deleting a resource is permanent and cascades to all related metrics and events. Associated data cannot be recovered after deletion. Archive a resource instead if you may need to reference it later.
</Warning>

Send a `DELETE` request to `/v1/resources/{id}`. A successful deletion returns `204 No Content` with an empty response body.

```bash
curl -X DELETE https://api.open-pmm.com/v1/resources/res_04ef1a3b5c7dg2hi8jklmn4o \
  -H "Authorization: Bearer $OPEN_PMM_API_KEY"
```

The API returns `204 No Content` with no response body when the deletion succeeds. If the resource has already been deleted or the `id` was never valid, the API returns `404 Not Found`.
