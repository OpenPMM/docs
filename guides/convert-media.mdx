A destination can refuse an image that another destination accepts. Instagram
accepts JPEG only. Facebook accepts 4 MB. LinkedIn accepts a maximum pixel
count. A conversion makes a new file that obeys these limits.

OpenPMM always keeps your original file. A conversion adds a file; it does not
replace one.

In the app, OpenPMM converts an image automatically when you attach it to a
destination. The API converts it when you publish or schedule the Post. You do
not confirm a safe conversion.

## What OpenPMM converts

OpenPMM makes these safe technical changes:

| Change | Example |
| --- | --- |
| The format | A PNG becomes a JPEG for Instagram. |
| The file size | A 6 MB image becomes smaller for Facebook. |
| The pixel count | A very large image becomes smaller for LinkedIn. |
| The stored rotation | A rotation tag becomes the actual pixels. |
| The metadata | OpenPMM removes the camera and location metadata. |
| The transparency | Transparent pixels become white when the destination requires JPEG. |

OpenPMM keeps the aspect ratio for every one of these changes.

## What OpenPMM does not convert

These changes change what the image shows, so you make them yourself:

- **A crop or a pad.** Instagram accepts an aspect ratio between 4:5 and
  1.91:1. A 9:16 image or a 3:1 banner needs a crop or a pad.
- **The animation.** OpenPMM does not make an animated GIF into a still image.

For these, use another file, or remove the destination.

## Convert an image before publication

You usually do not need this operation. OpenPMM creates the required file when
you publish or schedule the Post.

Use the conversion operation when you want to create and inspect the file
before publication.

<Steps>
  <Step title="Find the problem">
    Send `POST /workspaces/{workspace_id}/assets/{asset_id}/validations` with
    your destination IDs. Look at `can_convert` in each issue.
  </Step>
  <Step title="Convert the image">
    Send `POST /workspaces/{workspace_id}/assets/{asset_id}/conversions` with
    the same destination IDs and an `Idempotency-Key` header. The response is
    the finished file. There is no job to wait for.
  </Step>
  <Step title="Publish">
    Publish the post as usual. OpenPMM uses the converted file for the
    destinations that need it, and the original file for the others.
  </Step>
</Steps>

```bash
openpmm assets convert ast_01JABCDEF \
  --workspace ws_01JABCDEF \
  --destination dst_01JABCDEF \
  --json
```

In the app, OpenPMM converts the image when you attach it. The dialog only shows
a problem that needs your decision or a conversion retry.

```json
{
  "id": "rendition_01JABCDEF",
  "object": "asset_conversion",
  "asset_id": "ast_01JABCDEF",
  "media_kind": "image",
  "state": "ready",
  "content_type": "image/jpeg",
  "byte_size": 2411008,
  "width": 1440,
  "height": 1440,
  "created_at": "2026-08-12T10:04:11.000Z",
  "ready_at": "2026-08-12T10:04:11.000Z"
}
```

## Conversions are reused

OpenPMM keeps a conversion and reuses it. The same file and the same
destinations always give the same result, and OpenPMM does the work one time.

## A published post keeps its file

When you confirm a post, OpenPMM records the exact file that the post
publishes. A later change to a destination limit, or a later conversion, does
not change a post that you already confirmed.

## When a conversion is not possible

OpenPMM answers `422` with a reason:

| Reason | What to do |
| --- | --- |
| The image is animated. | Use a still image, or remove the destination. |
| The destinations accept no common format. | Publish to fewer destinations. |
| The destination publishes video only. | Attach a video for that destination. |

OpenPMM converts an image up to 24 megapixels and 50 MB. A larger file needs a
smaller version first.
