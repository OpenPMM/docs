The Open PMM CLI brings the full power of the API to your terminal, letting you create and query resources, record metrics, and log events without writing a single line of code. It is also designed as a first-class tool for agent-driven automation — structured JSON output, predictable exit codes, and composable commands make it straightforward to pipe CLI output directly into an AI agent's context.

<Note>
  The Open PMM CLI is coming soon and is not yet available for download. This page documents the planned interface so you can plan integrations in advance. Commands and flags are subject to change before the stable release.
</Note>

## Installation

Choose the installation method that best fits your environment.

<CodeGroup>
  ```bash npm
  npm install -g @open-pmm/cli
  ```

  ```bash Homebrew
  brew install open-pmm/tap/pmm
  ```

  ```bash Linux / macOS
  # Download and run the install script
  curl -fsSL https://releases.open-pmm.com/cli/install.sh | bash
  ```

  ```powershell Windows
  # Run in PowerShell
  irm https://releases.open-pmm.com/cli/install.ps1 | iex
  ```
</CodeGroup>

After installation, confirm the CLI is available:

```bash
pmm --version
```

## Authentication

The CLI needs your API key to communicate with Open PMM. You have two options.

**Option 1 — Interactive login**

Run the login command and follow the prompts. The CLI stores your credentials in a local config file (`~/.config/open-pmm/credentials`).

```bash
pmm auth login
```

**Option 2 — Environment variable**

Set `OPEN_PMM_API_KEY` before running any command. This takes precedence over the stored credential and is the preferred approach for automated and agent workflows.

```bash
export OPEN_PMM_API_KEY=your_key_here
pmm resources list
```

To confirm the CLI can reach the API with your current credentials, run:

```bash
pmm auth whoami
```

## Commands overview

<Tabs>
  <Tab title="Resources">
    Manage the core entities in your Open PMM account.

    | Command | Description |
    |---|---|
    | `pmm resources list` | List all resources. Supports `--type` and `--status` filters. |
    | `pmm resources get <id>` | Fetch a single resource by ID. |
    | `pmm resources create` | Create a new resource interactively or via flags. |
    | `pmm resources update <id>` | Update one or more fields on an existing resource. |
    | `pmm resources delete <id>` | Permanently delete a resource and its related data. |

    ```bash
    # List only active initiatives
    pmm resources list --type initiative --status active

    # Create a resource using flags
    pmm resources create --name "Search Improvements" --type feature --status draft

    # Update the status of a resource
    pmm resources update res_04ef1a3b5c7dg2hi8jklmn4o --status active
    ```
  </Tab>

  <Tab title="Metrics">
    Record and retrieve metric values associated with resources.

    | Command | Description |
    |---|---|
    | `pmm metrics list` | List recorded metrics. Supports `--resource-id` filter. |
    | `pmm metrics record` | Record a new metric value against a resource. |

    ```bash
    # List all metrics for a specific resource
    pmm metrics list --resource-id res_04ef1a3b5c7dg2hi8jklmn4o

    # Record a new metric value
    pmm metrics record \
      --resource-id res_04ef1a3b5c7dg2hi8jklmn4o \
      --name "weekly_active_users" \
      --value 4821
    ```
  </Tab>

  <Tab title="Events">
    Log and inspect events tied to resources in your account.

    | Command | Description |
    |---|---|
    | `pmm events list` | List events. Supports `--resource-id` and `--type` filters. |
    | `pmm events create` | Log a new event against a resource. |

    ```bash
    # Log a deployment event against a resource
    pmm events create \
      --resource-id res_04ef1a3b5c7dg2hi8jklmn4o \
      --type deployment \
      --description "Shipped Payments v2 to production"

    # List all events for a resource
    pmm events list --resource-id res_04ef1a3b5c7dg2hi8jklmn4o
    ```
  </Tab>
</Tabs>

## Using the CLI in agent workflows

The CLI outputs JSON by default, making it easy to feed structured data directly into AI agent contexts. Pass `--output json` on any command to ensure machine-readable output even if the default changes in a future version.

The following example shows a shell session where an AI agent uses the CLI to gather context about active initiatives, record a metric, and log a completion event — all without interacting with the HTTP API directly.

```bash
# 1. Fetch all active initiatives and pipe the JSON into your agent's context
pmm resources list --type initiative --status active --output json

# Example output
# {
#   "data": [
#     {
#       "id": "res_04ef1a3b5c7dg2hi8jklmn4o",
#       "name": "Payments v2",
#       "type": "initiative",
#       "status": "active"
#     }
#   ],
#   "has_more": false
# }

# 2. Agent decides to record a weekly metric for the initiative
pmm metrics record \
  --resource-id res_04ef1a3b5c7dg2hi8jklmn4o \
  --name "sprint_velocity" \
  --value 38 \
  --output json

# 3. Agent logs a status update event
pmm events create \
  --resource-id res_04ef1a3b5c7dg2hi8jklmn4o \
  --type "status_update" \
  --description "Sprint 12 completed. Velocity: 38 points." \
  --output json

# 4. Archive the initiative once work is confirmed complete
pmm resources update res_04ef1a3b5c7dg2hi8jklmn4o --status archived --output json
```

<Tip>
  Pass `--output json` in every command when scripting. This guarantees stable, parseable output regardless of terminal formatting or future changes to the CLI's default display style.
</Tip>
