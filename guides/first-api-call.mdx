The Open PMM API gives you programmatic access to all your product management data. This guide walks you through authenticating, listing resources, and creating your first resource — all from the command line using curl. By the end, you'll have confirmed your credentials work and understand what a typical API response looks like.

## Prerequisites

Before you begin, make sure you have the following:

- An **Open PMM API key** — see the [Authentication guide](/authentication) if you haven't generated one yet.
- **curl** installed on your system, or any HTTP client such as Postman, Insomnia, or HTTPie.
- A terminal or shell environment.

<Tip>
  Store your API key in an environment variable rather than pasting it directly into commands. This prevents accidental exposure in shell history, logs, or version control.
</Tip>

## Steps

<Steps>
  <Step title="Set your API key as an environment variable">
    Export your API key into your current shell session so every subsequent command can reference it without hard-coding the value.

    ```bash
    export OPEN_PMM_API_KEY=your_key_here
    ```

    You can verify the variable is set by running:

    ```bash
    echo $OPEN_PMM_API_KEY
    ```

    To persist this across sessions, add the `export` line to your shell profile (`~/.bashrc`, `~/.zshrc`, or equivalent).
  </Step>

  <Step title="List resources">
    Send a `GET` request to the `/v1/resources` endpoint. The `Authorization` header carries your Bearer token, and the `Content-Type` header tells the API you're working with JSON.

    ```bash
    curl https://api.open-pmm.com/v1/resources \
      -H "Authorization: Bearer $OPEN_PMM_API_KEY" \
      -H "Content-Type: application/json"
    ```

    If your key is valid, the API returns a `200 OK` response. If you receive a `401 Unauthorized` error, double-check that the environment variable is set correctly and that the key hasn't been revoked.
  </Step>

  <Step title="Inspect the response">
    A successful list response returns a JSON object containing a `data` array of resource objects alongside pagination metadata.

    ```json
    {
      "data": [
        {
          "id": "res_01hx3k9m2p4qr8st5uvwxy0z",
          "name": "Mobile App Redesign",
          "type": "initiative",
          "status": "active",
          "created_at": "2024-11-14T09:22:31Z",
          "updated_at": "2024-11-14T09:22:31Z"
        },
        {
          "id": "res_02ab7c1d3e5fg9hi6jklmn2o",
          "name": "Checkout Flow",
          "type": "feature",
          "status": "draft",
          "created_at": "2024-11-10T14:05:18Z",
          "updated_at": "2024-11-12T08:44:02Z"
        }
      ],
      "next_cursor": "cursor_eyJpZCI6InJlc18wMmFiN2MxZDNlNWZnOWhpNmprbG1uMm8ifQ",
      "has_more": true
    }
    ```

    | Field | Description |
    |---|---|
    | `data` | Array of resource objects matching your query. |
    | `next_cursor` | An opaque string you pass as `?cursor=` to fetch the next page. |
    | `has_more` | `true` when additional pages exist beyond the current response. |

    When `has_more` is `false`, you've reached the last page of results.
  </Step>

  <Step title="Create a resource">
    Send a `POST` request to `/v1/resources` with a JSON body describing the new resource. The `name` and `type` fields are required; `status` and `metadata` are optional.

    ```bash
    curl -X POST https://api.open-pmm.com/v1/resources \
      -H "Authorization: Bearer $OPEN_PMM_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Dark Mode Support",
        "type": "feature",
        "status": "draft",
        "metadata": {
          "priority": "high",
          "owner": "design-team"
        }
      }'
    ```

    A successful creation returns a `201 Created` response containing the full resource object:

    ```json
    {
      "id": "res_03cd9e2f4g6hi0jk7lmnop3q",
      "name": "Dark Mode Support",
      "type": "feature",
      "status": "draft",
      "metadata": {
        "priority": "high",
        "owner": "design-team"
      },
      "created_at": "2024-11-15T11:30:00Z",
      "updated_at": "2024-11-15T11:30:00Z"
    }
    ```

    Save the returned `id` — you'll use it to read, update, or delete the resource in subsequent requests.
  </Step>
</Steps>
