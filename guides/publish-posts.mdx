---
title: "Create posts"
description: "Validate a request, create posts, and check their status."
---

Publishing creates content on a provider. Validate the complete request before you publish. Then send the same request with confirmation and an idempotency key.

<Steps>
  <Step title="Build one post per destination">
    Each post needs a destination ID and a non-empty `body` array. For X, the array can contain a thread. For other channels, the array contains one item.

    ```json
    {
      "confirmed": true,
      "when": "now",
      "posts": [
        {
          "destination_id": "dst_example",
          "headline": null,
          "body": ["A release update from OpenPMM."],
          "media": [],
          "options": null
        }
      ]
    }
    ```
  </Step>
  <Step title="Validate without publishing">
    Send the complete payload to `POST /workspaces/{workspace_id}/post-validations`. Keep `confirmed: true` in the request. The endpoint does not save data or contact a provider.
  </Step>
  <Step title="Create the post">
    Send the validated payload to `POST /workspaces/{workspace_id}/posts`. Add a unique `Idempotency-Key` header.
  </Step>
  <Step title="Check the post status">
    The response contains a `posts` array. Store each post `id`. Use `GET /workspaces/{workspace_id}/posts/{post}` to get the current state.
  </Step>
</Steps>

<Warning>
  A timeout does not mean that publishing failed. Retry the same request with the same idempotency key. A new key can create a duplicate post.
</Warning>
