Each section covers the exact usage syntax, all accepted flags, and a working example you can adapt to your own workflows. </Note>

## Resources

Use `pmm resources` commands to create, inspect, update, and delete the product resources tracked in Open PMM.

<Accordion title="pmm resources list">

**Usage**

```bash
pmm resources list [flags]
```

**Description**

Returns a paginated list of all resources in your organisation. Use `--filter` to narrow results by name or type, and `--sort` to control ordering.

**Flags**

| Flag | Type | Default | Description |
|---|---|---|---|
| `--limit` | `integer` | `20` | Maximum number of resources to return (max `100`) |
| `--cursor` | `string` | — | Pagination cursor returned by a previous list response |
| `--filter` | `string` | — | Filter expression, e.g. `type:service` or `status:active` |
| `--sort` | `string` | `created_at:desc` | Sort field and direction, e.g. `name:asc` |
| `--output` | `json\|table\|yaml` | `table` | Output format |

**Example**

```bash
# List the 10 most recently created active services
pmm resources list \
  --limit 10 \
  --filter "type:service status:active" \
  --sort created_at:desc \
  --output table
```

</Accordion>

<Accordion title="pmm resources get <id>">

**Usage**

```bash
pmm resources get <id> [flags]
```

**Description**

Fetches a single resource by its ID and prints the full record, including all metadata fields.

**Arguments**

| Argument | Required | Description |
|---|---|---|
| `id` | Yes | The unique identifier of the resource, e.g. `res_04ab2` |

**Flags**

| Flag | Type | Default | Description |
|---|---|---|---|
| `--output` | `json\|table\|yaml` | `table` | Output format |

**Example**

```bash
pmm resources get res_04ab2 --output json
```

```json
{
  "id": "res_04ab2",
  "name": "Checkout Service",
  "type": "service",
  "status": "active",
  "metadata": {},
  "created_at": "2024-11-01T09:00:00Z",
  "updated_at": "2024-11-01T09:00:00Z"
}
```

</Accordion>

<Accordion title="pmm resources create">

**Usage**

```bash
pmm resources create --name <name> --type <type> [--status <status>] [--metadata <json>]
```

**Description**

Creates a new resource in your organisation and returns the created record. You must supply a name and type. Status defaults to `active` if omitted.

**Flags**

| Flag | Type | Required | Description |
|---|---|---|---|
| `--name` | `string` | Yes | Human-readable name for the resource |
| `--type` | `string` | Yes | Resource type, e.g. `service`, `feature`, `component` |
| `--status` | `string` | No | Initial status: `active`, `inactive`, or `archived` (default: `active`) |
| `--metadata` | `json` | No | Arbitrary key-value pairs as a JSON string |

**Example**

```bash
pmm resources create \
  --name "Payment Gateway" \
  --type service \
  --status active \
  --metadata '{"team":"payments","region":"us-east-1"}'
```

```json
{
  "id": "res_07cd4",
  "name": "Payment Gateway",
  "type": "service",
  "status": "active",
  "metadata": {
    "team": "payments",
    "region": "us-east-1"
  },
  "created_at": "2024-11-15T14:32:00Z"
}
```

</Accordion>

<Accordion title="pmm resources update <id>">

**Usage**

```bash
pmm resources update <id> [--name <name>] [--status <status>] [--metadata <json>]
```

**Description**

Applies a partial update to an existing resource. Only the flags you supply are changed; omitted fields retain their current values. Metadata is merged by default — pass `--metadata-replace` to overwrite the entire metadata object.

**Arguments**

| Argument | Required | Description |
|---|---|---|
| `id` | Yes | The unique identifier of the resource to update |

**Flags**

| Flag | Type | Description |
|---|---|---|
| `--name` | `string` | New display name |
| `--status` | `string` | New status: `active`, `inactive`, or `archived` |
| `--metadata` | `json` | Key-value pairs to merge into the existing metadata |
| `--metadata-replace` | — | When set, replaces the entire metadata object instead of merging |

**Example**

```bash
# Archive a resource and update its team metadata
pmm resources update res_04ab2 \
  --status archived \
  --metadata '{"team":"platform"}'
```

</Accordion>

<Accordion title="pmm resources delete <id>">

**Usage**

```bash
pmm resources delete <id> [--confirm]
```

**Description**

Permanently deletes a resource and all associated data. This action is irreversible. The CLI prompts for confirmation unless you pass `--confirm`.

<Warning>
  Deleting a resource also removes all metrics and events associated with it. This cannot be undone.
</Warning>

**Arguments**

| Argument | Required | Description |
|---|---|---|
| `id` | Yes | The unique identifier of the resource to delete |

**Flags**

| Flag | Type | Description |
|---|---|---|
| `--confirm` | — | Skip the interactive confirmation prompt (useful in scripts) |

**Example**

```bash
# Delete with confirmation prompt
pmm resources delete res_04ab2

# Delete non-interactively in a script
pmm resources delete res_04ab2 --confirm
```

</Accordion>

## Metrics

Use `pmm metrics` commands to list recorded metrics or push new measurements against a resource.

<Accordion title="pmm metrics list">

**Usage**

```bash
pmm metrics list [--resource-id <id>] [flags]
```

**Description**

Returns a paginated list of metric records. Omit `--resource-id` to list metrics across all resources in your organisation, or supply it to scope results to a single resource.

**Flags**

| Flag | Type | Default | Description |
|---|---|---|---|
| `--resource-id` | `string` | — | Scope results to a specific resource |
| `--limit` | `integer` | `20` | Maximum number of records to return (max `100`) |
| `--cursor` | `string` | — | Pagination cursor from a previous response |
| `--output` | `json\|table\|yaml` | `table` | Output format |

**Example**

```bash
# Fetch the 5 most recent metrics for a specific resource as JSON
pmm metrics list \
  --resource-id res_04ab2 \
  --limit 5 \
  --output json
```

```json
[
  {
    "id": "met_001",
    "resource_id": "res_04ab2",
    "name": "p99_latency_ms",
    "value": 142,
    "unit": "milliseconds",
    "recorded_at": "2024-11-15T14:45:00Z"
  }
]
```

</Accordion>

<Accordion title="pmm metrics record">

**Usage**

```bash
pmm metrics record --resource-id <id> --name <name> --value <number> --unit <unit>
```

**Description**

Records a new metric measurement against a resource. All four flags are required. The `--value` flag accepts integers and floating-point numbers.

**Flags**

| Flag | Type | Required | Description |
|---|---|---|---|
| `--resource-id` | `string` | Yes | ID of the resource this metric belongs to |
| `--name` | `string` | Yes | Metric name, e.g. `p99_latency_ms`, `error_rate` |
| `--value` | `number` | Yes | Numeric measurement value |
| `--unit` | `string` | Yes | Unit of measurement, e.g. `milliseconds`, `percent`, `bytes` |

**Example**

```bash
pmm metrics record \
  --resource-id res_04ab2 \
  --name "error_rate" \
  --value 0.42 \
  --unit percent
```

<Tip>
  Use consistent metric names and units across recordings to get accurate time-series aggregations in the API and dashboard.
</Tip>

</Accordion>

## Events

Use `pmm events` commands to list historical events or publish new ones to the event stream.

<Accordion title="pmm events list">

**Usage**

```bash
pmm events list [--resource-id <id>] [flags]
```

**Description**

Returns a paginated list of events. Scope the results to a specific resource with `--resource-id`, or omit it to retrieve events organisation-wide.

**Flags**

| Flag | Type | Default | Description |
|---|---|---|---|
| `--resource-id` | `string` | — | Filter events to a specific resource |
| `--limit` | `integer` | `20` | Maximum number of events to return (max `100`) |
| `--cursor` | `string` | — | Pagination cursor from a previous response |
| `--output` | `json\|table\|yaml` | `table` | Output format |

**Example**

```bash
# List the last 20 events across all resources
pmm events list --output table

# List events for a specific resource
pmm events list --resource-id res_04ab2 --limit 5 --output json
```

</Accordion>

<Accordion title="pmm events create">

**Usage**

```bash
pmm events create --type <type> --payload <json>
```

**Description**

Publishes a new event to the Open PMM event stream. The `--type` flag identifies the event category, and `--payload` accepts a JSON string containing any relevant context data you want to attach.

**Flags**

| Flag | Type | Required | Description |
|---|---|---|---|
| `--type` | `string` | Yes | Event type identifier, e.g. `deployment.completed`, `incident.opened` |
| `--payload` | `json` | Yes | Arbitrary JSON payload attached to the event |

**Example**

```bash
pmm events create \
  --type "deployment.completed" \
  --payload '{"resource_id":"res_04ab2","version":"v2.4.1","env":"production"}'
```

```json
{
  "id": "evt_09ef6",
  "type": "deployment.completed",
  "payload": {
    "resource_id": "res_04ab2",
    "version": "v2.4.1",
    "env": "production"
  },
  "created_at": "2024-11-15T16:00:00Z"
}
```

</Accordion>

## Webhooks

Use `pmm webhooks` commands to manage the HTTP endpoints that receive real-time event notifications from Open PMM.

<Accordion title="pmm webhooks list">

**Usage**

```bash
pmm webhooks list [flags]
```

**Description**

Lists all webhook endpoints registered in your organisation, including their subscribed event types and current status.

**Flags**

| Flag | Type | Default | Description |
|---|---|---|---|
| `--output` | `json\|table\|yaml` | `table` | Output format |

**Example**

```bash
pmm webhooks list --output table
```

```bash
# Output:
# ID          URL                                   EVENTS                            STATUS
# wh_001      https://hooks.example.com/openpmm     resource.created, metrics.rec…    active
```

</Accordion>

<Accordion title="pmm webhooks create">

**Usage**

```bash
pmm webhooks create --url <url> --events <event-types...>
```

**Description**

Registers a new webhook endpoint. Open PMM sends a POST request to the specified URL whenever any of the subscribed event types occur. Pass multiple event types as a space-separated list.

**Flags**

| Flag | Type | Required | Description |
|---|---|---|---|
| `--url` | `string` | Yes | The HTTPS endpoint that will receive event payloads |
| `--events` | `string...` | Yes | One or more event types to subscribe to |

**Supported event types**

| Event type | Description |
|---|---|
| `resource.created` | A new resource was created |
| `resource.updated` | An existing resource was updated |
| `resource.deleted` | A resource was deleted |
| `metrics.recorded` | A new metric measurement was recorded |
| `event.created` | A new event was published to the stream |

**Example**

```bash
pmm webhooks create \
  --url https://hooks.example.com/openpmm \
  --events resource.created resource.updated metrics.recorded
```

```json
{
  "id": "wh_002",
  "url": "https://hooks.example.com/openpmm",
  "events": ["resource.created", "resource.updated", "metrics.recorded"],
  "status": "active",
  "created_at": "2024-11-15T16:10:00Z"
}
```

<Note>
  Open PMM signs every webhook payload with an `X-OpenPMM-Signature` header so you can verify the request is genuine. See the API reference for signature verification details.
</Note>

</Accordion>

<Accordion title="pmm webhooks delete <id>">

**Usage**

```bash
pmm webhooks delete <id> [--confirm]
```

**Description**

Permanently removes a webhook endpoint. Open PMM immediately stops delivering events to the associated URL. The CLI prompts for confirmation unless you pass `--confirm`.

**Arguments**

| Argument | Required | Description |
|---|---|---|
| `id` | Yes | The unique identifier of the webhook to delete |

**Flags**

| Flag | Type | Description |
|---|---|---|
| `--confirm` | — | Skip the interactive confirmation prompt |

**Example**

```bash
# Delete with confirmation prompt
pmm webhooks delete wh_002

# Delete non-interactively
pmm webhooks delete wh_002 --confirm
```

</Accordion>
