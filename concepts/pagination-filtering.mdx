Every list endpoint in the Open PMM API returns results in pages rather than all at once. This keeps response sizes predictable, makes streaming large datasets safe, and lets you resume interrupted traversals without re-fetching data you have already processed. Open PMM uses **cursor-based pagination** — rather than page numbers, you receive an opaque cursor string that points to your position in the result set.

## The Response Envelope

All list endpoints — including `GET /resources`, `GET /metrics`, and `GET /events` — wrap their results in the same standard envelope:

```json
{
  "data": [ /* array of objects */ ],
  "next_cursor": "eyJpZCI6ImEzYmIxODllIn0",
  "has_more": true
}
```

<ResponseField name="data" type="array" required>
  The array of objects for the current page. May be empty if no results match your filters.
</ResponseField>

<ResponseField name="next_cursor" type="string | null" required>
  An opaque string you pass as the `cursor` query parameter to fetch the next page. `null` when there are no more results.
</ResponseField>

<ResponseField name="has_more" type="boolean" required>
  `true` if additional pages exist beyond the current one. When `false`, you have reached the last page and `next_cursor` will be `null`.
</ResponseField>

---

## Pagination Parameters

Pass these query parameters on any list request to control page size and position.

<ParamField query="limit" type="integer" default="20">
  The maximum number of objects to return in a single page. Accepted range is **1–100**. Requests above 100 are clamped to 100 without an error.
</ParamField>

<ParamField query="cursor" type="string">
  The opaque cursor returned as `next_cursor` in a previous response. Omit this parameter to start from the beginning of the result set.
</ParamField>

### Fetching the First Page

```bash
curl https://api.openpmm.io/v1/resources \
  --header "Authorization: Bearer $OPEN_PMM_API_KEY"
```

### Fetching the Next Page

Take the `next_cursor` value from the previous response and pass it as the `cursor` parameter:

```bash
curl "https://api.openpmm.io/v1/resources?cursor=eyJpZCI6ImEzYmIxODllIn0" \
  --header "Authorization: Bearer $OPEN_PMM_API_KEY"
```

<Note>
  Cursors are **opaque** — their internal encoding may change without notice. Do not parse, decode, or construct cursor strings yourself. Do not persist cursors for longer than a single traversal session; they may expire or become invalid after the underlying data changes.
</Note>

## Filtering

Narrow a list result to only the objects you need using the `filter[field]=value` query syntax. You may combine multiple filter parameters in one request; all conditions are applied with logical AND.

<ParamField query="filter[field]" type="string">
  Replace `field` with the name of any filterable attribute on the object type you are querying. The value is matched exactly (case-sensitive). For example, `filter[status]=active` returns only resources whose `status` equals `"active"`.
</ParamField>

### Filterable Fields by Endpoint

| Endpoint | Filterable fields |
|---|---|
| `GET /resources` | `type`, `status` |
| `GET /metrics` | `resource_id`, `name` |
| `GET /events` | `resource_id`, `type` |
| `GET /webhooks` | *(none)* |

### Example: Filter by Status

```bash
curl "https://api.openpmm.io/v1/resources?filter[status]=active" \
  --header "Authorization: Bearer $OPEN_PMM_API_KEY"
```

## Sorting

Control the order of results with the `sort` query parameter.

<ParamField query="sort" type="string" default="created_at">
  The field to sort by. Prefix the field name with `-` (a hyphen) to sort in **descending** order. For example, `sort=created_at` returns oldest records first; `sort=-created_at` returns newest records first.
</ParamField>

### Supported Sort Fields

Most list endpoints support sorting by `created_at`, `updated_at`, and `name`. Check the individual endpoint reference for the full list.

## Combining Pagination, Filtering, and Sorting

You can use all three mechanisms together in a single request. The example below fetches the second page of active resources, ordered by most recently updated, with 50 results per page:

<CodeGroup>

```bash curl
curl "https://api.openpmm.io/v1/resources\
?filter[status]=active\
&sort=-updated_at\
&limit=50\
&cursor=eyJpZCI6ImEzYmIxODllIn0" \
  --header "Authorization: Bearer $OPEN_PMM_API_KEY"
```

```python Python
import httpx

params = {
    "filter[status]": "active",
    "sort": "-updated_at",
    "limit": 50,
    "cursor": "eyJpZCI6ImEzYmIxODllIn0",
}

response = httpx.get(
    "https://api.openpmm.io/v1/resources",
    headers={"Authorization": f"Bearer {OPEN_PMM_API_KEY}"},
    params=params,
)
envelope = response.json()
resources = envelope["data"]
next_cursor = envelope["next_cursor"]
```

```javascript JavaScript
const params = new URLSearchParams({
  "filter[status]": "active",
  sort: "-updated_at",
  limit: "50",
  cursor: "eyJpZCI6ImEzYmIxODllIn0",
});

const response = await fetch(
  `https://api.openpmm.io/v1/resources?${params}`,
  { headers: { Authorization: `Bearer ${OPEN_PMM_API_KEY}` } }
);
const { data: resources, next_cursor } = await response.json();
```

</CodeGroup>

The response follows the standard envelope:

```json
{
  "data": [
    {
      "id": "a3bb189e-8bf9-3888-9912-ace4e6543002",
      "name": "Checkout Flow",
      "type": "feature",
      "status": "active",
      "metadata": { "owner": "platform-team" },
      "created_at": "2024-03-15T08:30:00.000Z",
      "updated_at": "2024-05-22T14:11:42.000Z"
    }
    /* …49 more objects */
  ],
  "next_cursor": "eyJpZCI6ImI0Y2MyOTBmIn0",
  "has_more": true
}
```

## Iterating All Pages

To traverse a full result set, loop until `has_more` is `false`:

```python
import httpx

client = httpx.Client(headers={"Authorization": f"Bearer {OPEN_PMM_API_KEY}"})

cursor = None
all_resources = []

while True:
    params = {"filter[status]": "active", "sort": "-updated_at", "limit": 100}
    if cursor:
        params["cursor"] = cursor

    envelope = client.get(
        "https://api.openpmm.io/v1/resources", params=params
    ).json()

    all_resources.extend(envelope["data"])

    if not envelope["has_more"]:
        break

    cursor = envelope["next_cursor"]

print(f"Fetched {len(all_resources)} resources.")
```

<Tip>
  Always use the maximum `limit=100` when iterating all pages in a batch job. Fewer round-trips means faster completion and lower risk of cursor expiry mid-traversal.
</Tip>
