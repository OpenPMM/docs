---
title: "Posts and publishing"
description: "Learn how drafts, posts, and publishing states work."
---

A **post** contains content for one destination. It also contains the current publishing state.

Set `when` to control what OpenPMM creates:

| `when` value | Result | Can contact a provider? |
| --- | --- | --- |
| `draft` | Editable channel drafts in a post group | No |
| `now` | Posts that start publishing now | Yes |
| ISO 8601 timestamp | Scheduled posts | Yes, at the scheduled time |

The create response contains a `posts` array. Each post has a state such as `scheduled`, `processing`, `published`, or `failed`.

## Confirmation

Requests that can publish must contain `confirmed: true`. OpenPMM rejects the request when confirmation is absent.

Use the validation endpoint before you create posts. Validation checks the same request but does not save data or contact a provider.

## Post submissions

OpenPMM records posts that were created together. The API currently returns this record as a `send_group`. Use the post submission endpoint when you must inspect all posts from one confirmed request.

<Warning>
  A timeout does not prove that publishing failed. Retry the same request with the same idempotency key. Do not create a new request until you check the post status.
</Warning>
