Open PMM represents all of its state through four object types: Resources, Metrics, Events, and Webhooks. Every field in every response maps to one of these shapes. This page documents each field, its type, its constraints, and shows a canonical JSON example you can use as a reference while building integrations.

<Info>
  All IDs across the Open PMM API are **UUIDs v4** (e.g., `"a3bb189e-8bf9-3888-9912-ace4e6543002"`). All timestamps are **ISO 8601 strings in UTC**, always including milliseconds (e.g., `"2024-06-01T12:00:00.000Z"`).
</Info>

---

## Resources

A resource is the primary entity in Open PMM. It can represent a product, a feature, a team, a service — any named thing your organization wants to track metrics and events against. Resources support a free-form `metadata` map so you can attach domain-specific context without requiring schema changes.

### Fields

<ResponseField name="id" type="string (UUID)" required>
  The unique identifier for this resource. Assigned by the API on creation and immutable thereafter.
</ResponseField>

<ResponseField name="name" type="string" required>
  A human-readable label for the resource. Must be between 1 and 255 characters.
</ResponseField>

<ResponseField name="type" type="string" required>
  A category tag you define, such as `"product"`, `"feature"`, or `"service"`. Used for filtering and grouping.
</ResponseField>

<ResponseField name="status" type="string" required>
  The current lifecycle state of the resource. Common values are `"active"`, `"inactive"`, and `"archived"`. You may define additional values for your organization.
</ResponseField>

<ResponseField name="metadata" type="object">
  An arbitrary key-value map for storing custom attributes. Keys must be strings; values may be strings, numbers, or booleans. Nested objects are not supported.
</ResponseField>

<ResponseField name="created_at" type="string (ISO 8601 UTC)" required>
  The timestamp at which the resource was created. Set by the API and read-only.
</ResponseField>

<ResponseField name="updated_at" type="string (ISO 8601 UTC)" required>
  The timestamp of the most recent update to the resource. Updated automatically by the API on every write.
</ResponseField>

### Example

```json
{
  "id": "a3bb189e-8bf9-3888-9912-ace4e6543002",
  "name": "Checkout Flow",
  "type": "feature",
  "status": "active",
  "metadata": {
    "owner": "platform-team",
    "priority": "high",
    "launch_quarter": "Q3-2024"
  },
  "created_at": "2024-03-15T08:30:00.000Z",
  "updated_at": "2024-05-22T14:11:42.000Z"
}
```

## Metrics

A metric is a single time-stamped numeric measurement attached to a resource. Metrics are append-only — you record new values over time rather than updating existing ones, which preserves a full historical series for every resource.

### Fields

<ResponseField name="id" type="string (UUID)" required>
  The unique identifier for this metric record. Assigned by the API on creation.
</ResponseField>

<ResponseField name="resource_id" type="string (UUID)" required>
  The ID of the resource this metric belongs to. Must reference an existing resource.
</ResponseField>

<ResponseField name="name" type="string" required>
  The metric key, such as `"conversion_rate"` or `"p99_latency_ms"`. Combined with `resource_id`, this forms the logical series name.
</ResponseField>

<ResponseField name="value" type="number" required>
  The numeric measurement. May be an integer or a floating-point number. Negative values are permitted.
</ResponseField>

<ResponseField name="unit" type="string">
  A human-readable label for the unit of measure, such as `"percent"`, `"ms"`, or `"requests"`. Not validated by the API — use it consistently for your own tooling.
</ResponseField>

<ResponseField name="recorded_at" type="string (ISO 8601 UTC)" required>
  The timestamp at which the measurement was taken. You provide this value so you can backfill historical data. Defaults to the current server time if omitted on write.
</ResponseField>

### Example

```json
{
  "id": "c7f3a1d2-4e5b-6789-abcd-ef0123456789",
  "resource_id": "a3bb189e-8bf9-3888-9912-ace4e6543002",
  "name": "conversion_rate",
  "value": 3.47,
  "unit": "percent",
  "recorded_at": "2024-05-22T00:00:00.000Z"
}
```

## Events

An event records that something meaningful happened on or around a resource. Events are immutable once written — they form a permanent, ordered log. The `payload` field carries structured data specific to each event `type`, allowing downstream systems (including webhooks) to act on fine-grained context.

### Fields

<ResponseField name="id" type="string (UUID)" required>
  The unique identifier for this event. Assigned by the API on creation.
</ResponseField>

<ResponseField name="type" type="string" required>
  A dot-namespaced string identifying the event category, such as `"resource.status_changed"` or `"metric.threshold_exceeded"`. Use these values when configuring webhook subscriptions.
</ResponseField>

<ResponseField name="resource_id" type="string (UUID)" required>
  The ID of the resource this event is associated with.
</ResponseField>

<ResponseField name="payload" type="object" required>
  A JSON object containing event-specific data. The shape of `payload` varies by `type` and is documented in the Events reference.
</ResponseField>

<ResponseField name="occurred_at" type="string (ISO 8601 UTC)" required>
  The timestamp at which the event occurred in your system. Like `metric.recorded_at`, you may supply this to support backfilling. Defaults to the current server time if omitted.
</ResponseField>

### Example

```json
{
  "id": "d9e4b2f1-0a1b-2c3d-4e5f-6a7b8c9d0e1f",
  "type": "resource.status_changed",
  "resource_id": "a3bb189e-8bf9-3888-9912-ace4e6543002",
  "payload": {
    "previous_status": "inactive",
    "new_status": "active",
    "changed_by": "user_01j2k3l4m5n6p7q8r9s0"
  },
  "occurred_at": "2024-05-22T14:11:42.000Z"
}
```

## Webhooks

A webhook is an outbound HTTP callback that Open PMM uses to push event notifications to your infrastructure. When an event of a subscribed type is recorded, Open PMM sends a signed `POST` request to your registered URL within seconds. Every delivery includes an `X-OpenPMM-Signature` header you can use to verify authenticity.

### Fields

<ResponseField name="id" type="string (UUID)" required>
  The unique identifier for this webhook registration.
</ResponseField>

<ResponseField name="url" type="string (HTTPS URL)" required>
  The endpoint Open PMM will POST event payloads to. Must use HTTPS. Open PMM will not deliver to plain HTTP endpoints.
</ResponseField>

<ResponseField name="events" type="string[]" required>
  An array of event type strings this webhook subscribes to, e.g. `["resource.status_changed", "metric.threshold_exceeded"]`. Use `["*"]` to subscribe to all event types.
</ResponseField>

<ResponseField name="secret" type="string" required>
  A shared secret used to generate the HMAC-SHA256 signature on each delivery. You provide this on creation; Open PMM never returns it in subsequent reads (it is write-only).
</ResponseField>

<ResponseField name="created_at" type="string (ISO 8601 UTC)" required>
  The timestamp at which the webhook was registered. Set by the API and read-only.
</ResponseField>

### Example

```json
{
  "id": "f1e2d3c4-b5a6-7890-cdef-012345678901",
  "url": "https://hooks.example.com/open-pmm",
  "events": [
    "resource.status_changed",
    "metric.threshold_exceeded"
  ],
  "secret": "••••••••••••••••",
  "created_at": "2024-04-01T09:00:00.000Z"
}
```

<Warning>
  The `secret` field is **write-only**. The API returns `"••••••••••••••••"` in place of the actual value after creation. Store your secret securely at registration time — you cannot retrieve it later. If you lose it, delete the webhook and create a new one.
</Warning>
