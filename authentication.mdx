Every request to the Open PMM API must include a valid API key. Open PMM uses the industry-standard Bearer token scheme — you generate a key from your dashboard, then pass it in the `Authorization` header of each HTTP request. There are no session cookies, no OAuth redirects for server-to-server calls, and no SDK required.

## Get an API key

1. Sign in to your account at [app.open-pmm.com](https://app.open-pmm.com).
2. Go to **Settings → API Keys**.
3. Click **Create Key**, enter a descriptive name, and select the appropriate scope (see [Token scopes](#token-scopes) below).
4. Copy the key — it is shown in full **only once**. Store it in a password manager or secrets vault immediately.

<Warning>
  Never embed an API key directly in source code or commit it to version control. Use environment variables, a secrets manager (e.g. AWS Secrets Manager, HashiCorp Vault, Doppler), or your CI/CD platform's secret store. If a key is ever exposed, revoke it immediately from **Settings → API Keys** and issue a replacement.
</Warning>

## Pass the key in requests

Include your key as a Bearer token in the `Authorization` header on every request.

```http
Authorization: Bearer <your-api-key>
```

curl -v https://api.open-pmm.com/v1/resources \

```python Python (full example)
import os
import requests

def get_resources(page: int = 1, per_page: int = 20) -> dict:
    """Fetch a page of Open PMM resources."""
    return requests.get(
        "https://api.open-pmm.com/v1/resources",
        headers={"Authorization": f"Bearer {os.environ['OPEN_PMM_API_KEY']}"},
        params={"page": page, "per_page": per_page},
        timeout=10,
    ).json()
```

```javascript Node.js (full example)
async function getResources(page = 1, perPage = 20) {
  const url = new URL("https://api.open-pmm.com/v1/resources");
  url.searchParams.set("page", page);
  url.searchParams.set("per_page", perPage);

  const res = await fetch(url, {
    headers: { Authorization: `Bearer ${process.env.OPEN_PMM_API_KEY}` },
  });

  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();
}
```

## Token scopes

When you create an API key you must assign it one of three scopes. Follow the principle of least privilege — use the narrowest scope that satisfies your integration's needs.

| Scope | Permissions |
|---|---|
| `read` | GET requests only — list and retrieve any resource, metric, or event |
| `write` | All `read` permissions plus POST, PUT, PATCH, and DELETE on resources, metrics, and events |
| `admin` | All `write` permissions plus key management (create, list, revoke) and account-level settings |

## Authentication errors

Open PMM returns standard HTTP status codes when authentication fails. Check the `error` field in the response body for a machine-readable code and a human-readable `message`.

### 401 Unauthorized

Returned when the `Authorization` header is missing, malformed, or contains an invalid or revoked key.

```json
{
  "error": {
    "code": "unauthorized",
    "message": "The API key provided is missing or invalid. Verify your Authorization header and try again.",
    "status": 401
  }
}
```

### 403 Forbidden

Returned when the key is valid but does not have the scope required to perform the requested action. For example, attempting a POST with a `read`-scoped key.

```json
{
  "error": {
    "code": "forbidden",
    "message": "Your API key does not have the required scope for this action. This endpoint requires the 'write' scope.",
    "status": 403
  }
}
```

<Info>
  A `403` error does **not** mean your key is invalid — it means you need a key with a higher scope. Issue a new `write` or `admin` key for the operation you're attempting.
</Info>

## Rotate or revoke a key

To rotate a key, go to **Settings → API Keys**, locate the key you want to replace, click **Revoke**, and then create a new key with the same scope. Update all consumers of the old key before revoking it to avoid downtime.

To revoke a key immediately (for example, after a suspected leak), click **Revoke** — the key is invalidated within seconds. Any in-flight request signed with the revoked key will receive a `401` response.
