Resources are the core organizational unit in Open PMM. They represent products, features, initiatives, or milestones — anything you want to track metrics and events against. Every metric record and product event links back to a resource, so defining your resource hierarchy is typically the first step when integrating with the API.

## GET /v1/resources

Retrieve a paginated list of resources in your workspace. Use the query parameters to filter by status or type, sort the results, and page through large sets with a cursor.

### Query Parameters

<ParamField query="limit" type="integer">
  Maximum number of resources to return per page. Defaults to `20`. Maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor returned in the previous response's `next_cursor` field. Omit to start from the beginning.
</ParamField>

<ParamField query="filter[status]" type="string">
  Filter results to resources with this status. Accepted values: `active`, `draft`, `archived`.
</ParamField>

<ParamField query="filter[type]" type="string">
  Filter results to resources of this type. Accepted values: `product`, `feature`, `initiative`, `milestone`.
</ParamField>

<ParamField query="sort" type="string">
  Field to sort by, optionally prefixed with `-` for descending order. Example: `-created_at`. Sortable fields: `name`, `created_at`, `updated_at`.
</ParamField>

### Response Fields

<ResponseField name="data" type="array">
  Array of resource objects.

  <Expandable title="Resource object">
    <ResponseField name="id" type="string">
      Unique resource identifier (UUID v4).
    </ResponseField>
    <ResponseField name="name" type="string">
      Human-readable name of the resource.
    </ResponseField>
    <ResponseField name="type" type="string">
      Resource type: `product`, `feature`, `initiative`, or `milestone`.
    </ResponseField>
    <ResponseField name="status" type="string">
      Current status: `active`, `draft`, or `archived`.
    </ResponseField>
    <ResponseField name="metadata" type="object">
      Arbitrary key-value pairs you attached to the resource.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when the resource was created.
    </ResponseField>
    <ResponseField name="updated_at" type="string">
      ISO 8601 timestamp of the most recent update.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Cursor to pass as `cursor` in your next request to retrieve the following page. `null` when you have reached the last page.
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of resources matching the current filters.
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl -G https://api.open-pmm.com/v1/resources \
  -H "Authorization: Bearer <key>" \
  -d limit=2 \
  -d "filter[status]=active" \
  -d "filter[type]=feature" \
  -d sort=-created_at
```

## POST /v1/resources

Create a new resource. Supply a `name` and `type` at minimum; all other fields are optional.

### Body Parameters

<ParamField body="name" type="string" required>
  A human-readable name for the resource. Must be between 1 and 255 characters.
</ParamField>

<ParamField body="type" type="string" required>
  The resource type. Accepted values: `product`, `feature`, `initiative`, `milestone`.
</ParamField>

<ParamField body="status" type="string">
  Initial status of the resource. Accepted values: `active`, `draft`, `archived`. Defaults to `draft`.
</ParamField>

<ParamField body="metadata" type="object">
  A free-form JSON object for storing additional context — team ownership, priority, external IDs, or any other key-value data you need.
</ParamField>

### Response Fields

<ResponseField name="data" type="object">
  The newly created resource object.

  <Expandable title="Resource object">
    <ResponseField name="id" type="string">
      Unique resource identifier (UUID v4).
    </ResponseField>
    <ResponseField name="name" type="string">
      Name of the resource as provided.
    </ResponseField>
    <ResponseField name="type" type="string">
      Resource type as provided.
    </ResponseField>
    <ResponseField name="status" type="string">
      Status of the resource, either as provided or defaulting to `draft`.
    </ResponseField>
    <ResponseField name="metadata" type="object">
      Metadata object as provided, or an empty object if omitted.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of resource creation.
    </ResponseField>
    <ResponseField name="updated_at" type="string">
      ISO 8601 timestamp, equal to `created_at` immediately after creation.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl -X POST https://api.open-pmm.com/v1/resources \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Mobile Push Notifications",
    "type": "feature",
    "status": "draft",
    "metadata": {
      "team": "growth",
      "quarter": "Q3-2024"
    }
  }'
```

```json Response
{
  "data": {
    "id": "res_03kz4m1o5r6s7t8u9v0w1x2y",
    "name": "Mobile Push Notifications",
    "type": "feature",
    "status": "draft",
    "metadata": {
      "team": "growth",
      "quarter": "Q3-2024"
    },
    "created_at": "2024-05-15T11:30:00Z",
    "updated_at": "2024-05-15T11:30:00Z"
  }
}
```
</CodeGroup>

## PUT /v1/resources/{id}

Update an existing resource. Send only the fields you want to change — any field you omit keeps its current value.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the resource to update.
</ParamField>

### Body Parameters

<ParamField body="name" type="string">
  A new human-readable name for the resource.
</ParamField>

<ParamField body="type" type="string">
  A new resource type. Accepted values: `product`, `feature`, `initiative`, `milestone`.
</ParamField>

<ParamField body="status" type="string">
  A new status. Accepted values: `active`, `draft`, `archived`.
</ParamField>

<ParamField body="metadata" type="object">
  A replacement metadata object. The entire `metadata` field is replaced by what you send; use a merge strategy in your client if you want to preserve existing keys.
</ParamField>

### Response Fields

<ResponseField name="data" type="object">
  The updated resource object, identical in shape to the [GET /v1/resources/{id}](#get-v1-resources-id) response.
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl -X PUT https://api.open-pmm.com/v1/resources/res_03kz4m1o5r6s7t8u9v0w1x2y \
  -H "Authorization: Bearer <key>" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "active",
    "metadata": {
      "team": "growth",
      "quarter": "Q3-2024",
      "launch_date": "2024-08-01"
    }
  }'
```

```json Response
{
  "data": {
    "id": "res_03kz4m1o5r6s7t8u9v0w1x2y",
    "name": "Mobile Push Notifications",
    "type": "feature",
    "status": "active",
    "metadata": {
      "team": "growth",
      "quarter": "Q3-2024",
      "launch_date": "2024-08-01"
    },
    "created_at": "2024-05-15T11:30:00Z",
    "updated_at": "2024-05-15T14:05:22Z"
  }
}
```
</CodeGroup>

## DELETE /v1/resources/{id}

Permanently delete a resource.

<Warning>
  Deleting a resource cascades to all associated metrics and events. This data cannot be recovered. Archive the resource instead (`status: archived`) if you want to preserve historical records.
</Warning>

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the resource to delete.
</ParamField>

### Response

Returns HTTP `204 No Content` on success with an empty response body.

### Example

<CodeGroup>
```bash cURL
curl -X DELETE https://api.open-pmm.com/v1/resources/res_03kz4m1o5r6s7t8u9v0w1x2y \
  -H "Authorization: Bearer <key>"
```

```json Response
// 204 No Content — empty body
```
</CodeGroup>
