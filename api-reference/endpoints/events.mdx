Events capture significant occurrences in your product's lifecycle — feature launches, milestone completions, production incidents, experiment conclusions, or any other moment worth recording. Unlike metrics, which track continuous numeric values, events are discrete occurrences with an arbitrary `payload` that carries structured context. You can link events to a resource or ingest them as standalone records and query them across type, resource, and time range.

## GET /events

Retrieve a paginated list of events. Narrow results with the filter parameters and use `occurred_after` / `occurred_before` to query a specific time window.

### Query Parameters

<ParamField query="type" type="string">
  Filter results to events of this type (e.g. `"feature.launched"`, `"incident.resolved"`). Exact string match.
</ParamField>

<ParamField query="resource_id" type="string">
  UUID of the resource to filter events by. When provided, only events linked to that resource are returned.
</ParamField>

<ParamField query="limit" type="integer">
  Maximum number of events to return per page. Defaults to `20`. Maximum is `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor returned in the previous response's `next_cursor` field. Omit to start from the beginning.
</ParamField>

<ParamField query="occurred_after" type="string">
  ISO 8601 timestamp. Returns only events that occurred at or after this time.
</ParamField>

<ParamField query="occurred_before" type="string">
  ISO 8601 timestamp. Returns only events that occurred at or before this time.
</ParamField>

### Response Fields

<ResponseField name="data" type="array">
  Array of event objects.

  <Expandable title="Event object">
    <ResponseField name="id" type="string">
      Unique event identifier (UUID v4).
    </ResponseField>
    <ResponseField name="type" type="string">
      The event type string as provided at creation.
    </ResponseField>
    <ResponseField name="resource_id" type="string">
      UUID of the linked resource, or `null` if the event is not associated with a resource.
    </ResponseField>
    <ResponseField name="payload" type="object">
      Arbitrary JSON payload containing event-specific context.
    </ResponseField>
    <ResponseField name="occurred_at" type="string">
      ISO 8601 timestamp of when the event took place.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when this record was ingested into Open PMM.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Cursor to pass as `cursor` on your next request. `null` when you have reached the last page.
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of events matching the current filters.
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl -G https://api.open-pmm.com/v1/events \
  -H "Authorization: Bearer <api-key>" \
  -d type=feature.launched \
  -d resource_id=res_03kz4m1o5r6s7t8u9v0w1x2y \
  -d occurred_after=2024-05-01T00:00:00Z \
```

## POST /events

Ingest a new event. Provide `type` at minimum. Attach an optional `payload` for structured context, link the event to a resource via `resource_id`, and set `occurred_at` to backfill historical events.

<Tip>
  Adopt a consistent dot-notation naming convention for event types (e.g. `feature.launched`, `incident.opened`, `milestone.completed`) to make filtering and webhook routing predictable across your team.
</Tip>

### Body Parameters

<ParamField body="type" type="string" required>
  A string identifier for the event type. Use a consistent naming convention such as `noun.verb` (e.g. `"feature.launched"`, `"experiment.concluded"`). Maximum 255 characters.
</ParamField>

<ParamField body="payload" type="object">
  A free-form JSON object containing event-specific data. Store anything relevant — user IDs, environment names, configuration values, or external references.
</ParamField>

<ParamField body="resource_id" type="string">
  UUID of the resource to associate this event with. The resource must already exist. If omitted, the event is stored without a resource link.
</ParamField>

<ParamField body="occurred_at" type="string">
  ISO 8601 timestamp indicating when the event took place. Defaults to the current UTC time if omitted. Use this field to backfill historical events.
</ParamField>

### Response Fields

<ResponseField name="data" type="object">
  The newly created event object.

  <Expandable title="Event object">
    <ResponseField name="id" type="string">
      Unique event identifier (UUID v4).
    </ResponseField>
    <ResponseField name="type" type="string">
      The event type string as provided.
    </ResponseField>
    <ResponseField name="resource_id" type="string">
      UUID of the linked resource, or `null` if none was provided.
    </ResponseField>
    <ResponseField name="payload" type="object">
      The payload object as provided, or an empty object if omitted.
    </ResponseField>
    <ResponseField name="occurred_at" type="string">
      ISO 8601 timestamp of when the event took place.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when this record was ingested into Open PMM.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl -X POST https://api.open-pmm.com/v1/events \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "milestone.completed",
    "resource_id": "res_03kz4m1o5r6s7t8u9v0w1x2y",
    "payload": {
      "milestone_name": "Beta Launch",
      "completed_by": "user_abc123",
      "notes": "All acceptance criteria met."
    },
    "occurred_at": "2024-05-15T17:00:00Z"
  }'
```

```json Response
{
  "data": {
    "id": "evt_03op4q5r6s7t8u9v0w1x2y3z",
    "type": "milestone.completed",
    "resource_id": "res_03kz4m1o5r6s7t8u9v0w1x2y",
    "payload": {
      "milestone_name": "Beta Launch",
      "completed_by": "user_abc123",
      "notes": "All acceptance criteria met."
    },
    "occurred_at": "2024-05-15T17:00:00Z",
    "created_at": "2024-05-15T17:00:02Z"
  }
}
```
</CodeGroup>

## GET /events/{id}

Retrieve a single event by its ID.

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the event to retrieve.
</ParamField>

### Response Fields

<ResponseField name="data" type="object">
  The event object.

  <Expandable title="Event object">
    <ResponseField name="id" type="string">
      Unique event identifier (UUID v4).
    </ResponseField>
    <ResponseField name="type" type="string">
      The event type string.
    </ResponseField>
    <ResponseField name="resource_id" type="string">
      UUID of the linked resource, or `null` if not associated.
    </ResponseField>
    <ResponseField name="payload" type="object">
      Arbitrary JSON payload attached to the event.
    </ResponseField>
    <ResponseField name="occurred_at" type="string">
      ISO 8601 timestamp of when the event took place.
    </ResponseField>
    <ResponseField name="created_at" type="string">
      ISO 8601 timestamp of when this record was ingested into Open PMM.
    </ResponseField>
  </Expandable>
</ResponseField>

### Example

<CodeGroup>
```bash cURL
curl https://api.open-pmm.com/v1/events/evt_03op4q5r6s7t8u9v0w1x2y3z \
  -H "Authorization: Bearer <api-key>"
```
